# AE101 M9 Round 2 — repository implementation audit

**Question:** Which open-source coding-agent projects actually implement capture → harvest → durable memory → promotion/review → next-run loading → measurement?

**Checked:** 2026-09-06. Moving-world cutoff: 2026-03-06. I pulled or freshly cloned each repository, pinned every code citation to the inspected commit, searched production call sites rather than accepting README claims, and ran targeted tests where the runtime was locally reproducible. No star counts were used.

## Verdict

No inspected repository implements the complete M9 chain: coding-session or execution-trace ingestion → candidate rule → explicit human accept/reject → durable agent-readable store → automatic later-run loading → measured improvement on a comparable later coding task.

- **Every closes the repository-knowledge return edge:** it can mine current and prior sessions, write one grounded learning, maintain the store, and make `ce-plan` search it later. Its promotion decision is agent-applied, however, and its tests validate artifact contracts rather than downstream task improvement. [`ce-compound`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/SKILL.md#L7-L26) `[practitioner direct]`; [`ce-plan` research](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-plan/references/research.md#L11-L45) `[practitioner direct]`.
- **The original Google Research ReasoningBank closes an automated trajectory-memory return edge and measures coding outcomes:** its SWE-bench runner retrieves one prior memory, runs the agent, self-judges the trace, distills up to three memories, appends them to JSONL, and repeats. It has no human promotion gate, and its correctness signal is an LLM judge. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L161-L263) `[academic/research]`; [paper Table 2 and limitations](https://arxiv.org/html/2509.25140#S4.T2) `[academic/research]`.
- **HumanLayer's exact ACE repository is publications, not an implementation.** At the inspected commit it contains Markdown essays and images, with no package manifest, source tree, tests, or executable loop. [Repository tree at `f2bc7ae`](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/tree/f2bc7aec4575418d2d2e83fec078266cc56d3e6a) `[practitioner direct]`.
- **The `claude-flow/ReasoningBank` lead resolves into two different projects.** The ReasoningBank derivative is in `ruvnet/agentic-flow`; it exposes storage/retrieval and legacy judge/distill functions, but its current alias requires caller-supplied labeled patterns, its hook scripts are not wired to an agent runtime, its fresh promotion governance is a separate unused surface, and its checked-in ReasoningBank tests currently fail at construction. The current `claude-flow` repository, now canonical at `ruvnet/ruflo`, instead has a genuine nightly DREAM code-improvement loop with durable history, frozen hypotheses, baseline/candidate evaluation, human reject/remediate/merge, and measured effects—but its orchestration prompt lives outside the repository and it improves product code rather than harvesting session corrections into rules. [`agentic-flow` exports](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/index.ts#L11-L39) `[practitioner direct]`; [DREAM ledger](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md#L1-L16) `[practitioner direct]`; [reviewed and merged DREAM PR #3169](https://github.com/ruvnet/ruflo/pull/3169) `[practitioner direct]`.

The positive proposition is therefore **L2 at best**: one academic team reports multi-benchmark gains and one practitioner project has a concrete repository-native knowledge pipeline, but no single project joins those mechanisms with human-approved promotion. This is not L3 convergence: there are fewer than 10–20 independent implementations, and the three agentic / replicable / measurable gates are not all met by any one project. [ReasoningBank paper](https://arxiv.org/html/2509.25140) `[academic/research]`; [Every implementation](https://github.com/EveryInc/compound-engineering-plugin/tree/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound) `[practitioner direct]`.

Full mode also discovers recent Claude Code, Codex, Cursor, Pi, and omp session records; it retains at most five and escalates only for a branch match or at least two topic-keyword matches. - **Durable artifact:** exactly one qualifying Markdown learning is created or updated under `<docs_root>/solutions/`; high overlap updates the existing document instead of creating a duplicate. `CONCEPTS.md` may also receive vocabulary from the same evidence. [`ce-compound`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/SKILL.md#L16-L26) `[practitioner direct]`; [`compounding-directive.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-setup/assets/compounding-directive.md#L5-L11) `[practitioner direct]`; [`refresh-and-discoverability.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/references/refresh-and-discoverability.md#L54-L90) `[practitioner direct]`.

This is a real prompt-level return edge, although it is tied to CE planning rather than every arbitrary agent start. [`ce-plan` research](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-plan/references/research.md#L11-L45) `[practitioner direct]`; [`learnings-researcher.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-plan/references/agents/learnings-researcher.md#L14-L28) `[practitioner direct]`.
- **Failure controls:** only the orchestrator writes tracked artifacts; session search has a relevance gate; invalid `docs_root` values fail closed; grounding has mechanical and semantic checks; stale or contradictory docs route to targeted refresh; non-interactive refresh cannot silently delete or cut accurate material. [`ce-compound`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/SKILL.md#L44-L60) `[practitioner direct]`; [`grounding-validation.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/references/grounding-validation.md#L1-L33) `[practitioner direct]`; [`durable-bar-parity.test.ts`](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/tests/durable-bar-parity.test.ts#L21-L40) `[practitioner direct]`.

## 3. Google Research / reasoning-bank — academic implementation baseline

**Inspected version:** [`ed80611`](https://github.com/google-research/reasoning-bank/commit/ed80611788292ea739f1effd31f16c53823b8a0d), committed 2026-05-18. The SWE-bench implementation entered the repository in the 2026-02-26 historical release; the WebArena memory/evaluator path was updated 2026-04-22. [SWE release commit](https://github.com/google-research/reasoning-bank/commit/1f334c1de85ded4d4511cc6303b52ac5661e863f) `[academic/research]`; [WebArena update](https://github.com/google-research/reasoning-bank/commit/50ce587925e4d0de70a5665b5c79b9221e54b759) `[academic/research]`.

### Implemented loop

- **Capture source:** for each SWE-bench issue, the runner saves the mini-swe-agent message trajectory, drops system messages, and joins the remaining content into a trace. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L200-L231) `[academic/research]`.
- **Harvest algorithm:** an LLM judge labels the trace success/failure; a second model call receives the issue plus trajectory and a label-specific prompt. The prompt asks for at most three generalized, non-overlapping memory items from either successful or failed experience. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L227-L263) `[academic/research]`; [`instruction.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/memory/instruction.py#L16-L61) `[academic/research]`.
- **Durable artifact:** every task appends its task id, query, status, and memory items to a model-specific JSONL file; a separate JSONL cache stores query embeddings. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L176-L182) `[academic/research]`; [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L227-L245) `[academic/research]`; [`memory_management.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/memory/memory_management.py#L168-L209) `[academic/research]`.
- **Promotion/review gate:** there is no candidate ledger or human acceptance. Each processed task is automatically distilled and appended; the only gate is the self-generated success/failure label plus prompt instructions against duplication. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L227-L245) `[academic/research]`.
- **Next-run loading:** before the next task, the runner embeds the new issue, selects the single most similar prior query, joins its memory items, and passes that text into `agent.run`. This is a direct executable return edge rather than a documentation promise. [`swebench.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/run/extra/swebench.py#L176-L209) `[academic/research]`; [`memory_management.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/memory/memory_management.py#L134-L166) `[academic/research]`.
- **Measurement:** the authors report SWE-bench Verified resolution rates of 38.8% vs 34.2% without memory for Gemini 2.5 Flash and 57.4% vs 54.0% for Gemini 2.5 Pro, with fewer average steps in both cases. They also compare against Synapse and report WebArena/Mind2Web results. This is an author-run multi-benchmark experiment—L2, not independent replication. [Paper Table 2](https://arxiv.org/html/2509.25140#S4.T2) `[academic/research]`; [experimental setup](https://arxiv.org/html/2509.25140#S4) `[academic/research]`.

### Failure controls and counterevidence

The memory prompt constrains count and overlap, and the paper studies sensitivity to judge error; however, the production loop has no human correction, held-out per-memory review, provenance beyond task id/status, staleness check, or rollback/promotion layer. The paper itself names dependence on LLM-as-judge labels as a limitation and proposes stronger verifiers, ensembles, or human feedback as future work. [`instruction.py`](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/third_party/src/minisweagent/memory/instruction.py#L23-L27) `[academic/research]`; [paper Appendix E](https://arxiv.org/html/2509.25140#A5) `[academic/research]`.

Fresh independent counterevidence cautions against generalizing one method's benchmark win: EvoMemBench's standardized comparison of 15 memory methods reports that long-context baselines remain competitive, memory helps most when context is insufficient or tasks are difficult, and no memory form wins consistently across settings. [EvoMemBench, 2026-05-18](https://arxiv.org/abs/2605.18421) `[academic/research]`.

**Evidence call:** L2 for an automated trace → memory → later coding-run loop with measured benchmark outcomes; it does not support the M9 claim about human-approved rule promotion. [ReasoningBank paper](https://arxiv.org/html/2509.25140) `[academic/research]`.

## 4. ruvnet / agentic-flow — ReasoningBank derivative audit

**Inspected version:** [`d3735a3`](https://github.com/ruvnet/agentic-flow/commit/d3735a33533da2e12a68439177a791bf1c5c91e1), committed 2026-07-29. ### What is implemented

- The exported `ReasoningBank` name currently aliases `HybridReasoningBank`. That class does **not** capture a coding trajectory: callers supply `sessionId`, task, input/output, critique, success, and reward to `storePattern`. It persists an AgentDB episode and, for a successful item with input/output, attempts to add a causal edge whose target is simply `episodeId + 1`, with confidence 0.8 and sample size 1. [`index.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/index.ts#L11-L26) `[practitioner direct]`; [`HybridBackend.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/HybridBackend.ts#L24-L34) `[practitioner direct]`; [`HybridBackend.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/HybridBackend.ts#L101-L129) `[practitioner direct]`.
- Retrieval and strategy recommendation are executable APIs, and consolidation can automatically create AgentDB skills once task groups clear `minUses` and `minSuccessRate`. There is no human review or cryptographic promotion in this ReasoningBank path. [`HybridBackend.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/HybridBackend.ts#L135-L185) `[practitioner direct]`; [`HybridBackend.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/HybridBackend.ts#L188-L257) `[practitioner direct]`; [`HybridBackend.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/HybridBackend.ts#L259-L307) `[practitioner direct]`.
- The legacy `runTask` function does implement retrieve → caller execution → judge → distill → optional consolidate, but it depends on the caller to turn retrieved memory into agent context and does not store the raw trajectory. [`index.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/index.ts#L98-L132) `[practitioner direct]`.
- The nominal pre-task hook only prints a memory block and says the agent system “should” capture/inject it; the post-task hook requires a caller-provided trajectory JSON file or stdin. A repository-wide call-site search at the pinned commit found these hook entrypoints referenced by documentation but not registered or invoked by production runtime code—an audited missing return edge. [`pre-task.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/hooks/pre-task.ts#L34-L75) `[practitioner direct]`; [`post-task.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/reasoningbank/hooks/post-task.ts#L36-L95) `[practitioner direct]`.

### Promotion, failure controls, and live test

The new MetaHarness governance code is materially stronger than ReasoningBank's own consolidation: it binds candidate and benchmark hashes into a receipt, requires an expiring signature from a trusted public key, and uses compare-and-swap against the evaluated baseline. But production reference search found `promoteCandidate` called only in its unit test; it is not connected to `storePattern`, `autoConsolidate`, or the hooks. This is a real governance component, not a closed learning loop. [`flywheel-governance.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/src/harness/flywheel-governance.ts#L81-L175) `[practitioner direct]`; [`flywheel-governance.test.ts`](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/agentic-flow/tests/harness/flywheel-governance.test.ts#L38-L114) `[practitioner direct]`; [ADR-077](https://github.com/ruvnet/agentic-flow/blob/d3735a33533da2e12a68439177a791bf1c5c91e1/docs/adr/ADR-077-ruvector-metaharness-governed-promotion.md#L14-L43) `[practitioner direct]`.

The legacy fallback judge treats a trace as successful when any serialized step contains “complete” and none contains “error”; when no API key is available, fallback distillation constructs a memory object but then returns an empty list without storing it. Stored LLM-distilled items have a source object but hard-code `evidence: []`. These are direct memory-pollution and silent-no-learning risks. ## 5. ruvnet/ruflo (`claude-flow`) — DREAM evaluated code-improvement loop

**Inspected version:** [`277c7bc`](https://github.com/ruvnet/ruflo/commit/277c7bc03ad192eef6d6f57e59ab7bab69a5728d), committed 2026-09-05 after human review and merge of DREAM PR #3169. `[practitioner direct]`

This is not ReasoningBank and does not ingest coding-session corrections. It is nevertheless the closest inspected implementation of a governed compounding engineering loop:

- **Capture and harvest:** a scheduled external routine reads the durable ledger, checks the fate of earlier issues/PRs, rotates through a domain, fans out research and architecture-review roles, grounds one gap in current code, and freezes a falsifiable hypothesis before evaluation. The 2026-09-03 run also acted after the same automation failure had recurred in three earlier gists, showing that prior-run state can change the next investigation. [DREAM ledger](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md#L1-L16) `[practitioner direct]`; [issue #3168 run record](https://github.com/ruvnet/ruflo/issues/3168) `[practitioner direct]`; [frozen hypothesis](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/dream-gist-2026-09-03.md#L39-L43) `[practitioner direct]`.
- **Durable artifact:** the loop leaves a research gist, issue, candidate branch/PR, evaluation evidence, and a ledger row containing finding, issue, PR, evaluated status, verdict, effect, witness, and earlier-run fates. The ledger is explicitly loaded at the start of later nights. [DREAM gist](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/dream-gist-2026-09-03.md#L45-L70) `[practitioner direct]`; [live ledger schema and rows](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md#L112-L133) `[practitioner direct]`.
- **Promotion/review gate:** candidates are evaluated but remain draft PRs requiring human review. For #3169, ruvnet rejected the first evidence package, requiring the automation change to be split out, green exact-head checks, a representative benchmark, malformed-input/no-leak cases, and determinism proof. The agent remediated those items; the PR then merged on 2026-09-05. [PR #3169 review and merge record](https://github.com/ruvnet/ruflo/pull/3169) `[practitioner direct]`; [post-rejection addendum](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/dream-gist-2026-09-03.md#L81-L91) `[practitioner direct]`.
- **Measurement:** the remediated retrieval change ran a labeled 18-document/6-topic benchmark across four settings and disclosed a losing region. At the production default, Recall@6 and nDCG@6 stayed constant while topic diversity rose 0.472→0.667 and duplicate rate fell 0.289→0.200; malformed-input and determinism tests were also added. These are direct component metrics for one accepted change, not proof that the overall coding agent improves over successive nights. [DREAM addendum](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/dream-gist-2026-09-03.md#L81-L91) `[practitioner direct]`; [merged commit](https://github.com/ruvnet/ruflo/commit/277c7bc03ad192eef6d6f57e59ab7bab69a5728d) `[practitioner direct]`.
- **Failure controls:** the run records a frozen hypothesis, baseline-isolated test, complete parameter sweep including regressions, adversarial critic, reward-hack checklist, security review, SHA-256 witness, and a no-self-merge policy. The human review proved the gate can reject inadequate evidence rather than rubber-stamp the agent's own verdict. [DREAM gist](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/dream-gist-2026-09-03.md#L39-L70) `[practitioner direct]`; [PR #3169](https://github.com/ruvnet/ruflo/pull/3169) `[practitioner direct]`.

The largest reproducibility gap is explicit: the scheduled routine and its prompt are external to `.github`, so the repo publishes results and state but not the complete orchestrator that produced them. The ledger itself also records the earlier v1 failure: 80 nightly research issues yielded only 4 shipped changes (5%), 1 rejection, and 75 untouched proposals (94%). Later, a multi-night block of ledger rows silently failed to reach `main` until branches were merged; the loop repeatedly had to recover state from issues and PRs. These are unusually useful zombie-work and broken-memory counterexamples. [DREAM ledger](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md#L1-L27) `[practitioner direct]`; [ledger recovery record](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md#L135-L160) `[practitioner direct]`.

**Evidence call:** L2 repeated single-project mechanism with real human rejection, remediation, merge, and component-level measurement. It does not establish M9's trace-to-rule proposition, and the missing public orchestrator prevents full replication. ## Implication for M9

The exercise should treat **run → inspect trace → human judgment → candidate harvest → explicit accept/reject → durable rule → fresh comparable run → diff** as the experimental method, not as settled industry practice. The missing mechanism worth making visible is the promotion ledger: preserve the trace excerpt and human rationale, record rejected candidates as well as accepted ones, and make a rule's next-run use observable. Ruflo's DREAM history supplies a concrete model for frozen hypotheses, adverse results, explicit rejection, remediation, and zombie-work tracking; Every supplies grounded repo-native capture and refresh; ReasoningBank supplies a measurable later-run design. The outcome should be measured against a fixed yardstick—correctness, interventions, steps, retries, or time-to-verified-fix—because artifact validity and retrieval success are not evidence of improved work. [DREAM ledger](https://github.com/ruvnet/ruflo/blob/277c7bc03ad192eef6d6f57e59ab7bab69a5728d/docs/dream-cycle/LEDGER.md) `[practitioner direct]`; [Every grounding contract](https://github.com/EveryInc/compound-engineering-plugin/blob/b159e1fa4c70efa995742269d38269bcc7524dd2/skills/ce-compound/references/grounding-validation.md) `[practitioner direct]`; [ReasoningBank measurement and judge limitation](https://arxiv.org/html/2509.25140#A5) `[academic/research]`; [HumanLayer on the human as judge](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/f2bc7aec4575418d2d2e83fec078266cc56d3e6a/wsff.md#L388-L405) `[practitioner direct]`.

**What was not found:** no implementation in this sweep consumes stored human feedback as an explicit **rule-promotion** signal; no project both versions repository-native rules and measures a controlled comparable-task improvement; no independent replication raises the full M9 loop to L3; and no evidence justifies presenting autonomous self-improvement as a typical production outcome. Ruflo consumes human PR feedback for code promotion, but does not turn that feedback into a durable behavioral rule.
