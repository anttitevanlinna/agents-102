# Headless learning agents: substrate and admission OODA Cycle — 2026-09-07 18:16

**Focus area:** What a Claude Code or Codex agent can safely change when it “learns” across disposable headless runs.
**Research mode:** Cross-platform pattern with a primary-research counter-test.
**Why this focus:** Earlier rounds established capture, promotion, and rerun mechanics but left five design questions open: where learning lives, what may be updated, how source authority survives consolidation, how conflicts are retained, and how a bad learning is reversed.

## Findings

### The run is disposable; the external substrate is the learner

**Sources:** https://code.claude.com/docs/en/memory — [vendor documentation]; https://code.claude.com/docs/en/headless — [vendor documentation]; https://learn.chatgpt.com/docs/agent-configuration/agents-md.md — [vendor documentation]; https://learn.chatgpt.com/docs/customization/memories.md — [vendor documentation]; https://learn.chatgpt.com/docs/non-interactive-mode.md — [vendor documentation]
**Date:** Live documentation checked 2026-09-07
**Agent level:** Personal / team
**What:** Claude Code begins each session with fresh context and reloads human-authored `CLAUDE.md` plus agent-written auto memory; Codex likewise loads instruction files per run and keeps local memory separate from team guidance. Both headless surfaces can preserve or discard run/session state, so continuity does not need to live inside the executor.
**Evidence level:** L0 capability evidence.
**Key claims:** Persistent behavior is carried by external artifacts—rules, skills, memory, evals, and harness code. Those are different update targets with different scopes. Platform memory is context, not an enforcement boundary; durable team rules belong in version-controlled instruction surfaces.

### Memory admission is an authorization decision

**Sources:** https://arxiv.org/abs/2607.14611 — [academic/research]; https://arxiv.org/abs/2608.01679 — [academic/research]; https://arxiv.org/abs/2608.12851 — [academic/research]
**Dates:** 2026-07-16, 2026-08-04, and 2026-08-13
**Agent level:** Personal / team
**What:** Bad Memory found that malicious content already present in Claude Code or Codex memory files could affect current and future sessions. AuthMem-Bench observed “authority collapse” in 48 of 49 consolidator/model configurations: systems preserved a claim but lost the source constraints governing how it could be reused. SkillMisevo found unsafe reusable artifacts in all 21 evolving configurations and fresh-session harm in 15, even though the source trajectories had succeeded on their task.
**Evidence level:** L2 across three recent research programs; no production replication.
**Key claims:** A successful trajectory is not sufficient evidence for promotion. Every durable item needs source, authority, scope, time, and permitted-use metadata; an agent must not turn a user report, repository text, tool output, or its own inference into a standing instruction merely by summarizing it.

### A learning lifecycle must preserve disagreement and make promotion reversible

**Sources:** https://arxiv.org/abs/2608.13921 — [academic/research]; https://arxiv.org/abs/2605.22794 — [academic/research]
**Dates:** 2026-08-14 and 2026-05-23
**Agent level:** Personal / team
**What:** TANGLE found that end-to-end memory extraction often loses the relations needed to represent unresolved conflicts, while models recognized conflicts more reliably than they calibrated actions or asked for missing context. MOSS provides counter-evidence that broader self-modification can improve a small task set when candidates are replayed in ephemeral workers, promoted through user consent, and protected by health-probe rollback.
**Evidence level:** L2 research prototypes.
**Key claims:** The store needs candidate, active, conflicted, rejected, superseded, expired, and rolled-back states rather than one canonical-answer slot. Promotion should be a versioned deployment with replay and rollback, not a write to an append-only memory file.

## What I Looked For But Did Not Find

I found no production system that assigns separate promotion authority to observations, rules, skills, tools, evals, harness code, and permissions; no public longitudinal evidence for reliable forgetting or rule retirement in Claude Code or Codex; and no common reproducibility bundle that links a headless run, environment, model, retrieved memories, candidate diff, human decision, and fresh-run outcome. The papers are recent preprints, not 10–20-practitioner convergence.

## Orientation

**The learning agent is a change-control system for its substrate.** The first design question is not “what should it remember?” but “what may this evidence authorize the next agent to believe or do?” Module 9 can start from that thesis: let the agent propose changes to rules, skills, tests, or harness code, but never let retrieved content promote its own authority or silently widen execution permissions.
