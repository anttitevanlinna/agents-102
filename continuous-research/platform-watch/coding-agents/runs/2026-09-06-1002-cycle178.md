# Calibrated agent action correctness: state-of-practice OODA cycle — 2026-09-06 10:02

**Focus area:** How practitioners calibrate whether a coding agent should act, and how they engineer the action itself toward correctness.
**Research mode:** People-first practitioner research, followed by a primary-research counter-test.
**Why this focus:** A learning agent can accumulate better rules and still take an unauthorized, mistimed, or semantically wrong action. This round tests what “absolute correctness” can defensibly mean once the agent is allowed to execute.

## Findings

### Mature practice calibrates the delegation boundary, then verifies the state transition

**Sources:** https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-code-review.md — [practitioner direct]; https://github.com/EveryInc/compound-engineering-plugin/blob/main/skills/ce-code-review/SKILL.md — [practitioner direct]; https://hamel.dev/blog/posts/evals-faq/ — [practitioner direct]; https://martinfowler.com/articles/harness-engineering.html — [practitioner direct]
**Dates:** current Every repository state inspected 2026-09-06; Hamel Husain and Shreya Shankar, modified 2026-09-01; Birgitta Böckeler, 2026-04-02
**Agent level:** Team
**What:** Every's current review pipeline separates severity, follow-up class, and apply permission. Review is report-only by default; `mode:agent` still cannot mutate; local application requires separate explicit authority; the skill never pushes. Husain and Shankar then decompose action evaluation into end-to-end success, tool choice, arguments, response, resulting state, authorization, and preconditions. Böckeler separates computational sensors—tests, types, linters, structural checks—from probabilistic semantic review and places cheap deterministic checks both inside the agent loop and in CI.
**Evidence level:** L2 implementation evidence from one practitioner project plus L1 current practitioner method; no measured calibration curve.
**Key claims:** A confidence or severity score is a routing signal, not permission. “The tool returned success” is not an outcome check: the action is evidenced only when preconditions held, the authorized call ran, the intended state transition occurred, and independent postconditions passed.

### The strongest public production case wins by selecting a narrow, reversible action class

**Source:** https://www.intercom.com/blog/ai-is-approving-our-pull-requests-heres-how-we-made-it-safe/ — [practitioner direct, vendor venue]
**Date:** 2026-04-21
**Agent level:** Team
**What:** Intercom decomposes PR review across specialist agents, grounds it in repo-specific guidance, refuses broad PRs, permits human escalation, logs the evidence, and keeps the shipping engineer accountable for monitoring and rollback. Its controlled pilot covered more than 100 PRs with zero reverts among AI-approved PRs and 6–16× faster p75 approval; the first four broader-rollout weeks included 497 fully autonomous PRs. Intercom reports 0.53% backend and 0.22% frontend revert rates for AI-authored code, versus 5.39% and 2.00% for human-authored code.
**Evidence level:** L2 single-company production experiment.
**Key claims:** The viable auto-action pool is deliberately narrow and reversible. The public report does not expose false-negative review rates, selection details, or independent replication; revert rate is also an incomplete proxy for semantic correctness.

### Models do not reliably know when to abstain; hard guarantees stop at the contract boundary

**Sources:** https://arxiv.org/abs/2607.10059 — [academic/research]; https://arxiv.org/abs/2607.05397 — [academic/research]; https://arxiv.org/abs/2606.19242 — [academic/research]
**Dates:** 2026-07-11, 2026-04-26, and 2026-06-17
**Agent level:** Team / company
**What:** AgentAbstain tests 263 act/abstain pairs across 42 executable sandboxes, 17 frontier models, and four harnesses. The best agent reached only 59.5% paired accuracy; task-solving ability and abstention were largely independent, and agents sometimes recognized the need to abstain only after an irreversible action. Proof of Execution instead moves assurance outside the model: it separates planning, enforcement, effect, and recordkeeping, with exclusive credentials and a signed causal trace; its single-node prototype rejected injected bypass and trace-mutation attacks at about 2.7 ms minimal-flow overhead. C-Trace formalizes a subset of GDPR policy over execution traces and intercepts tool calls and outputs. It reached 0% attack success under perfect extraction, but with 10% extractor noise attack success rose to at most 12% and false positives to at most 16%.
**Evidence level:** L2 research programs and prototypes, not production practice.
**Key claims:** Better models and verbal confidence do not remove the need for an external authority gate. A system can prove authorization, path compliance, trace integrity, and declared state transitions under explicit assumptions; it cannot prove that an underspecified human intention was correct. Formal guarantees inherit the limits of the contract and policy extraction.

## Current Practice Stack

1. **Evidence:** derive task-specific pass/fail checks from human-labelled failures; use deterministic assertions wherever the property is objective and validated judges only for semantic residue.
2. **Authority:** classify the action by blast radius and reversibility; route to `auto / ask / deny`; never let confidence alone grant mutation rights.
3. **Execution:** expose narrow typed tools; check authorization, preconditions, arguments, tool result, and resulting state.
4. **Containment:** work in a branch or sandbox; prefer small changes; place deterministic sensors before commit and again in CI.
5. **Recovery and proof:** retain the full causal trace, monitor the deployed effect, and keep rollback owned.

## What I Looked For But Did Not Find

No public coding-agent system demonstrates absolute semantic correctness across repositories, tasks, and model upgrades. I did not find a calibrated probability estimate that remains reliable across those changes; a 10–20-practitioner convergence on the full stack; an independent replication of Intercom's autonomous approval results; or a production coding-agent deployment of the formal execution-proof approaches. Current evidence supports layered risk reduction and hard guarantees for narrow declared invariants—not infallible action.

## Orientation

**Calibration is a property of the delegation system, not a feeling reported by the model.** The practical target is: act automatically only inside a narrow region where authorization, preconditions, expected state transition, deterministic postconditions, and rollback are all engineered. Outside that region, ask or abstain.

For Agents 101, this belongs after rule compounding: first make the agent remember; then make it earn authority. A compact exercise could present paired issues with one hidden permission or precondition change. Students build the `auto / ask / deny` router, verify state after every tool call, and are scored on both successful actions and correct abstentions.
