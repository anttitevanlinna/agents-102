### Finding 3: OpenAI Agents API Public Beta — Programmatic Successor to Assistants API (NEW)

**Source:** [openai.com/index/introducing-the-agents-api/](https://openai.com/index/introducing-the-agents-api/) — [vendor documentation]
**Source:** [marktechpost.com/2026/09/10/openai-launches-the-agents-api-in-public-beta-putting-the-codex-harness-behind-one-api-call](https://www.marktechpost.com/2026/09/10/openai-launches-the-agents-api-in-public-beta-putting-the-codex-harness-behind-one-api-call/) — [domain trade publication]
**Date:** September 10, 2026
**Agent level:** team / company
**What:** OpenAI launched the Agents API in public beta on September 10, 2026 — 15 days after the Assistants API hard stop (August 26). The Agents API exposes the managed harness that runs Codex as an API primitive. Four core concepts: agent, environment, session, events. Managed infrastructure layer handles: session orchestration, context compaction across long tasks, sub-agent coordination, lazy tool loading, crash recovery. Nine sandbox partners at launch: Blaxel AI, Cloudflare Dev, Daytona, DigitalOcean, E2B, Modal, Oracle Cloud, Runloop AI, Vercel. Pricing: no extra fee beyond model tokens, tool usage, and any hosted sandbox compute. **This is NOT a thread-management API** (like Assistants) — it is a cloud-hosted autonomous agent harness. Designed for "longer periods, tool use, and coordinating multiple helper agents."
**Evidence level:** Level 0 (launch announcement; no independent practitioner deployment accounts found at Day+6)
**Key claims:**
- OpenAI now offers a managed cloud harness (not just a model API) — infrastructure competition with Anthropic Managed Agents

- Nine infrastructure partners means external sandboxing is supported day one, not just OpenAI-hosted
- Relevant to T+30 Assistants API postmortem window (Sep 25): migration path now exists; question is whether practitioners migrated to Responses API or went directly to Agents API
