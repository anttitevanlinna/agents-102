## Findings

### Finding 1: Fable 5.1 released Sep 1 — positioned above Opus 5 for agentic work; becomes Claude Code default

**Source:** https://platform.claude.com/docs/en/models/fable-5-1/overview — [vendor documentation]
**Source:** https://releasebot.io/updates/anthropic/claude-code — [vendor documentation]
**Source:** https://simonwillison.net/2026/Sep/1/claude-fable-5-1/ — [practitioner direct]
**Date:** September 1, 2026
**Agent level:** personal / team
**What:** Claude Fable 5.1 released September 1. Specs: 1M context, 128K max output, $10/$50 per Mtok (input/output), cache reads at $0.25/MTok (75% reduction vs prior Fable models). Positioned for "demanding reasoning and long-horizon agentic work." Anthropic recommendation: "For most workloads, start with Claude Opus 5. Use Claude Fable 5.1 for demanding reasoning and long-horizon agentic work, or when your evals on Claude Opus 5 at higher effort still fall short." Claude Code v2.1.257 (Sep 1) made Fable 5.1 the default model — implicitly classifying all Claude Code tasks as "demanding reasoning and long-horizon agentic work." Three breaking changes vs Fable 5: forced tool use returns 400 error, thinking blocks tied to model (earlier models can't read them), editing earlier turns invalidates thinking blocks. Five additive: per-message effort (beta), turn-scoped system messages (beta), progress updates between tool calls (beta), lower cache read price, content provenance.
**Evidence level:** Level 1 (vendor documentation + one practitioner account of pelican benchmark — no deployer-direct production comparison)
**Key claims:**
- Fable 5.1 is now Claude Code's default model (v2.1.257, Sep 1)
- Fable 5.1 costs 2x Opus 5 ($10/$50 vs $5/$25 input/output) but Anthropic positions it as the correct choice for agentic workloads
- Cache read at $0.25/MTok (vs $0.50/MTok for Opus 5) creates 25-45% cost reduction on highly agentic/cached workloads
- Willison: notes Fable 5.1 release, focused on benchmark (Terminal-Bench-Science 52.6%) and pelican SVG test — no assessment of Claude Code default behavior change
- New env var `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` allows enterprises to pin subagent models independently of main session model
- Breaking change: forced tool use returns 400 — any pipeline using `tool_choice: {type: "tool"}` breaks silently on migration

### Finding 3: GitHub Copilot parallel agent sessions — 10-agent ceiling published; architectural enabler confirmed

**Source:** https://alphasignal.ai/news/github-s-copilot-app-lets-developers-run-10-parallel-ai-coding-agents-at-once — [tech press]
**Source:** https://ecorpit.com/github-copilot-app-parallel-agents-worktrees-guide-2026/ — [tech press]
**Source:** https://getbeam.dev/blog/run-multiple-ai-agents-parallel-guide.html — [practitioner analysis]
**Date:** September 3, 2026
**Agent level:** personal / team
**What:** GitHub Copilot app (available all plans since July 7) highlighted parallel agent sessions Sep 3: up to 10 agents per repository simultaneously, each isolated in its own Git worktree. Unified session view for monitoring. Getbeam guide (practitioner analysis, unnamed author): "The bottleneck is not determined by how many your API plan supports. It is determined by how many output streams you can meaningfully review in a single sitting." Practical ceiling identified as 3-4 streams before cognitive overhead negates gains. GitHub's 10-agent architectural limit vs the 3-4 cognitive limit is the operative tension.
**Evidence level:** Level 1 (vendor announcement + one practitioner analysis without named deployers)
**Key claims:**
- 10 = GitHub Copilot app architectural ceiling for parallel sessions per repository
- 3-4 = practitioner cognitive ceiling for meaningful parallel stream oversight (converges with Karpathy 3-4 interactive sessions)
- Git worktrees are the technical enabler — isolation prevents agents overwriting each other
- No practitioner reports of operating at or near the 10-session cap yet
- Platform ceiling (10) is 2.5x higher than cognitive ceiling (3-4) — the bottleneck is human review, not infrastructure
