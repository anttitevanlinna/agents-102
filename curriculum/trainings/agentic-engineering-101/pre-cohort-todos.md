## Hunt for buried gold

Moves are declared well across AE101. **Priors, mechanisms and why-it-works claims are not.** Those are a different species from a move, and a sweep shaped around *"which beat fails to name its move"* structurally cannot see them: a move is *do X*, a prior is *assume Y*, a mechanism is *it works because Z*. The recurring shape is not a missing sentence. The sentence exists, is correct, is well written, and sits somewhere with no weight: a fourth bullet, an item in an enumeration whose point is something else, link anchor text, or a supplementary that never reaches the deck.

### Verified in the current curriculum

Ranked by how much of AE101 the missing generalisation unlocks. All nine are open decisions; the evidence exists already, so the work is promotion or joining, not inventing theory.

1. **Agenticness is accumulated, not enabled.** [the-agent-loop.md](../../lectures/the-agent-loop.md) says the harness supplies context, tools and a loop, and that a long session merely keeps choosing next steps. [story-of-module-6.md](../../lectures/story-of-module-6.md) then shows an agent that had just written the training still opening in the un-packaged, chat-shaped form. The missing join is: the harness makes continuation possible; rules, durable state, checks and encoded corrections make continued work increasingly agentic. **Action:** decide which M6 synthesis beat states agenticness as an accumulated property of the working system rather than a product mode.
2. **Understanding and durable artefacts solve different continuity problems.** [how-this-training-was-built.md:33](../../lectures/how-this-training-was-built.md) lands *"Understanding is the artifact. Files can be re-made from it"*. [what-keeps-a-long-running-session-going.md:7](../../lectures/what-keeps-a-long-running-session-going.md) later lands the counterweight: live context fills; files survive. The first makes work recoverable by the person who understands it. The second makes work resumable and transferable by another session, agent or teammate. **Action:** qualify the first claim so it does not accidentally demote durable state.
3. **Compounding includes deletion.** [spot-gaps-build-the-loop.md:36](../../exercises/spot-gaps-build-the-loop.md) says rules files have a half-life: adding rules is only half; subtracting dead ones is the other half. The M6 compound ladder and Key Concepts carry accumulation but not subtraction. The general loop is *add → sharpen → delete*. Otherwise the context system compounds noise along with learning. **Action:** promote deletion into the M6 synthesis rather than leaving it inside one exercise bullet.
4. **Parallelism has a topology, not just a count.** The strongest rule sits in optional [workflow-composition-lineages.md](supplementary/workflow-composition-lineages.md): Cognition's parallel writers conflicted; a single writer with advisor/reviewer agents held. The general rule is to parallelise independent reads, investigations and reviews; serialise coupled writes and shared semantic decisions. Parallelism pays only when the gain beats coordination, conflict and merge cost. **Action:** decide where the core course names this before students equate more agents with more throughput.
5. **The diff and the transcript are two different evidence layers.** [diagnose-and-resend.md:26](../../exercises/diagnose-and-resend.md) says Git tells what the agent did while the transcript tells how it got there, including drift and dead ends. Outcome evidence without process evidence misses the mechanism of failure; process evidence without the diff misses what actually shipped. **Action:** promote the pair into the general diagnostic method instead of leaving it as M5 exercise logistics.
6. **Every check has a latency budget.** Optional [how-the-best-do-ci-cd.md:39](supplementary/how-the-best-do-ci-cd.md) cleanly separates fast deterministic checks in the inline path from slow qualitative evaluators in the background or at a deliberate gate. Core M5/M6 names verifiers, judges and gates but can leave them sounding interchangeable. **Action:** decide where the core theory teaches placement by latency: seconds inline, minutes asynchronously, expensive judgment at a named gate.
7. **Two of the three soil-line priors exist only as figure microtext.** [the-whole-map.md:84](../../lectures/the-whole-map.md)'s engine map closes on *"the soil it grows in: act under uncertainty · competence is the gate · a move counts when it crosses the wall"*, a 13.5px italic SVG caption strip; the derived M3/M6 map copies drop the strip. Without it, the M6 promote move looks failed in its first month. **Action:** decide whether the expectation earns a claim-shaped position in the M6 close or stays a trailing clause.

Supplementary and reference pages do not reach the composed Slides deck (`check_slides.md §10`). The recurring shape is that a beat's *checklist* is in-deck while the *reason it is not arbitrary* sits in the linked page. Scanned across all 46 in-deck files; these two survive.

- **Prompt injection's mechanism never reaches the room, and the beat that would carry it is a handoff, not a teaching beat.** [earn-the-trust.md:89](earn-the-trust.md) carries the checklist and the move (*"three legs, cut one"*) and links out. The reason lives only in [supplementary/the-lethal-trifecta.md:11](supplementary/the-lethal-trifecta.md): an LLM cannot reliably tell instructions from data, because everything in the window is one stream of tokens and no privileged channel marks which part came from you. Zero in-deck hits for that mechanism. Without it, *cut one leg* reads as an arbitrary three-item rule a student will negotiate down to *"I'll just scan the input"*, and the sentence that forecloses exactly that (*"A filter that mostly works is a gate that sometimes opens"*) reaches nobody.

 Scoped further 2026-08-07, and it widens: *trifecta*, *injection* and *untrusted* return **zero hits across all four M3 exercises and both M3 lectures**. The frame appears once in the whole security module, in `## Next`, framed as pre-flight before M4 grants more autonomy. So M3's hands-on work threat-models the student's feature and never points an audit at the agent shipping it, which is the row STRIDE structurally does not have (*"STRIDE models attacks on the system; the trifecta models attacks through the agent"*, supplementary slide 3).

 **Two decisions, different sizes.** (a) The cheap one: a seventh `## Key Concepts` bullet under the STRIDE/access-surface bullet it extends, carrying the mechanism unnamed so `## Next` still gets to land *prompt injection* and *the lethal trifecta* as names for a hole the student can already see. Drafted line: *"STRIDE models attacks on the system you're shipping. Nothing in it covers attacks on the agent shipping it, which reads instructions and data as one stream, so whatever it reads can steer it."* Key Concepts runs 119 words across six bullets, so there is room. (b) The real one: whether a security module whose four exercises never audit the agent is the module we want. That is a shape question, not a sentence question, and the bullet in (a) patches the concept without answering it.
- **The context-window prior is absent, and the absence is already a recorded decision.** [supplementary/token-efficiency.md](supplementary/token-efficiency.md) carries the counterintuitive half: a fuller window produces a worse answer, not merely a slower or pricier one. Zero in-deck hits. [the-loop-half-filled.md](../../lectures/the-loop-half-filled.md)'s maintainer block banks context-window capacity as a near-half law the closer skips, taught in the supplementary, *"It stays there."* The only in-deck trace is a link label pitching the thrift frame that page's first sentence exists to demolish. **Action:** the call is on the record; re-open it only if the long-run modules need students holding a trimmed window as a quality move rather than budget hygiene.

The pattern is per-file, not a policy problem. Checks-that-push-back closed on its own once [what-keeps-a-long-running-session-going.md:14](../../lectures/what-keeps-a-long-running-session-going.md) gave it an in-deck home with a named handle. ### Outside-in practitioner lens

This is an inference from published practice, not a claim that any named practitioner reviewed AE101. It asks what their strongest recurring arguments would add to the course after the ten curriculum-native joins above.

1. **Boris Cherny: automate recurring review comments into deterministic infrastructure.** Cherny's reported Meta practice was to log repeat review comments and write a lint rule after the pattern recurred three or four times ([Orosz interview](https://newsletter.pragmaticengineer.com/p/building-claude-code-with-boris-cherny)). AE101 teaches compounding and verifiers, but not the promotion threshold from judgment to automation. **Add:** a recurrence rule: observe first, count repetition, then turn a stable review pattern into a check.
2. **Boris Cherny and Kieran Klaassen: retrieval architecture is part of context engineering.** [token-efficiency.md:43](supplementary/token-efficiency.md) holds both practitioner moves: pass paths rather than pasted walls; let model-driven grep/glob retrieve what is needed; treat the folder as the agent's durable environment. **Add:** make context economics core theory, what enters the window, how long it stays, and why addressable files beat copied context.
3. **Armin Ronacher: review bandwidth governs safe generation throughput.** [The Final Bottleneck](https://lucumr.pocoo.org/2026/2/13/the-final-bottleneck/) frames unread output as an accumulating queue: when input outruns review, throttle, shed load or add a trustworthy downstream check. AE101 names backpressure, but does not yet teach work-in-progress as the governing quantity. **Add:** a WIP law: do not start another agent stream merely because a slot is free; start it only when the review system can absorb the return.
4. **Armin Ronacher: failed automation should be deleted, and negative knowledge should persist.** In [Agentic Coding Things That Didn't Work](https://lucumr.pocoo.org/2025/7/30/things-that-didnt-work/), Ronacher keeps automation only for repeated work, evaluates whether it improves results, and deletes helpers that do not become useful practice. **Add:** compound failed experiments too: record what was tried and the acceptance variance, then remove the dead helper so future agents do not rediscover or inherit it.
5. **Simon Willison: require enough understanding to remain an active participant.** [Understand to participate](https://simonwillison.net/2026/Jul/2/understand-to-participate/) names cognitive debt: as the agent's implementation outruns the human's model of it, the human loses the concepts needed to steer what comes next. Passing checks does not repay that debt. **Add:** a handoff comprehension gate, explain the changed system, demonstrate it, and identify the next safe change before ownership transfers.
6. **Simon Willison: encode the boundary, then delegate judgment inside it.** In [Fable's judgement](https://simonwillison.net/2026/Jul/3/judgement/), Willison reports better results from asking a capable model to decide when tests or lower-power subagents fit than from prescribing every branch. AE101 is strong on explicit rules and could imply that more prescription is always more mature. **Add:** a rule-to-judgment ladder: automate invariants, state constraints and evidence requirements, and leave reversible task-level choices to observable agent judgment.
7. **Hamel Husain and Shreya Shankar: error analysis comes before eval design.** Their [Evals FAQ](https://hamel.dev/blog/posts/evals-faq/evals-faq.pdf) starts the minimum viable setup with manual review of real traces and says the failure taxonomy should emerge from observed application behaviour. AE101 diagnoses one run and calibrates a judge, but does not leave the student with a growing case bank. **Add:** a durable failure dataset: real traces, human labels, failure clusters and the checks each cluster earned.
8. **Hamel Husain: keep exploration alive after the evaluator exists.** The same FAQ warns that targeted classifiers find failures already described by the classifier and recommends retaining random samples. A mature gate can make the team blind to novelty. **Add:** split monitoring into exploitation (known checks) and exploration (random or outlier traces), with a route for new failures to reshape the eval set.
9. **Matt Pocock: shared understanding is an explicit pre-build artefact.** Pocock's [grilling primitive](https://github.com/mattpocock/skills/blob/main/docs/productivity/grilling.md) descends a decision tree one dependency at a time, gives a recommended answer, lets the codebase settle what it can, and waits for explicit confirmation before enactment. AE101 uses this shape locally without fully naming it as reusable task shaping. **Add:** generalise the interview contract: one frontier question at a time until both sides can state the same decision tree.
10. **Kieran Klaassen: compounding is not complete until the next loop retrieves and tests the lesson.** The [Compound Engineering guide](https://every.to/guides/compound-engineering) asks whether the system would catch the issue automatically next time; writing a note alone is not the finish. **Add:** a retrieval test on every compound move: name the future trigger, the durable home, how the next session finds it, and the check that proves it fired.

### Enactment gaps, stated in the curriculum, never performed by the student

Surfaced 2026-08-08 by a coverage map of AE101 against two external practitioner accounts (Wollsén and McCrosky's Crawl/Walk/Run/Fly playbook, and Wollsén's 490-PR self-report; both filed at `continuous-research/observations/wollsen-fredrik.md`). Seven candidate gaps went to adversarial refutation and four died outright, because the curriculum teaches the concept under its own coined vocabulary (*verifier*, *backpressure*, *absorption*, blast radius) or inside a supplementary the search never opened. These three survived. They share one shape: **AE101 states the principle and never has the student perform it at full size.** That is what makes them cheap, no new theory, one beat each.

- **No agent ever answers a human reviewer.** PR creation is taught ([fix-tests-first.md:49](../../exercises/fix-tests-first.md), [close-the-ticket.md](../../exercises/close-the-ticket.md) § *Write the close-out and send it*), and read-the-failure-then-fix-until-green is taught as a runtime primitive ([reference/claude-code-for-engineers.md:239,247](reference/claude-code-for-engineers.md), `/loop` watching a build, `/goal "all tests pass"`). But the direction is inverted everywhere review comments appear: the agent *produces* them ([earn-the-trust.md:160](earn-the-trust.md), [map-the-access-surface.md:126](../../exercises/map-the-access-surface.md)) or *mines* them, never answers them. Purely IC-level, no permission needed, and it is the loop this audience lives in daily. **Not to be confused with agent-resolved merge conflicts, which are a decided doctrine pointing the other way** ([reference/multi-session-git.md:74](reference/multi-session-git.md): *"Do not let either agent resolve the conflict automatically"*), leave that alone. **Action:** decide whether one exercise step has the agent read a reviewer's comments and push the response, or whether this stays out of scope because cohort students have no live reviewer.

- **No beat exercises the running software at the moment the agent declares done.** Runtime verification exists on *reading* surfaces and at project bootstrap ([supplementary/build-a-project-from-zero.md:13](supplementary/build-a-project-from-zero.md) *"Open the page and play"*; [supplementary/skill-stacking.md](supplementary/skill-stacking.md)'s browser-QA workflows; [supplementary/how-the-best-do-ci-cd.md](supplementary/how-the-best-do-ci-cd.md) §6 on flags and rollback). What is missing is an in-room beat where the student runs the delivered thing before believing the claim, so every countermove to premature completion is a check the agent can satisfy **without the software ever having executed**. **This is deliberate at M5 and should not be "fixed" there**, [diagnose-and-resend.md:27](../../exercises/diagnose-and-resend.md) chooses it: *"You hold the three lenses. You are not holding the codebase."* The question is whether it should be absent from every module. Deploy and rollback stay out of scope; opening the thing is a different ask. **Action:** decide whether one line lands in M4's return-read or M5's verifier menu, *exercise the path a user takes, not only the check you wrote*.

- **The student never points an agent at a repo they do not own.** [close-the-ticket.md](../../exercises/close-the-ticket.md) § *Anything can be reverse-engineered* declares the licence in full (*"a codebase nobody documented, a CI pipeline, a config, an API you did not write, the system your team runs on and cannot explain"*) and then enacts it on one tracker ticket, admitting the scale in its own words: *"The ticket is that move at its smallest."* AE101 is single-repo by architecture, not oversight ([prework.md](prework.md) §1 *"Pick THE repo"*; [getting-going.md:10](getting-going.md) *"You'll stay in this one repo for the whole training"*), so this is a design decision rather than a missing slot. **Action:** decide whether a named M6 shape or a homework line carries the full-size version, or whether the single-repo contract wins and the declaration stays deliberately un-enacted.

### Tensions the theory rewrite must preserve

These are not inconsistencies to smooth away. Each pair identifies a boundary the course needs to teach.

- **Parallel generation versus accountable absorption.** Klaassen's direction increases concurrent generation; Ronacher's direction limits starts by trustworthy review capacity. Both can be true because bottlenecks migrate. Available agent slots measure production capacity; acceptable WIP is governed by how much returned work the verification and review system can absorb. **Action:** teach concurrency and WIP as different quantities, with a decision rule for when another stream helps and when it only lengthens the unread queue.
- **Encoded rules versus delegated judgment.** AE101 teaches durable instructions and deterministic checks; Willison shows the value of letting a capable agent choose reversible tactics inside explicit boundaries. The mature system is neither rule-free nor maximally prescribed: encode invariants, constraints and evidence requirements; delegate observable, reversible choices; remove rules that no longer earn their context cost. **Action:** make the rule-to-judgment boundary explicit so compounding does not become instruction accretion.

One structural note falls out of the same hunt:

- **The declaration affordance in AE101 is grammatical, not a widget, and it is currently accidental.** Across the 93 body headings in the thirteen exercise files, every one is an imperative or a phase label except [close-the-ticket.md](../../exercises/close-the-ticket.md)'s *"Anything can be reverse-engineered"*. Lecture headings are the opposite: claims (*"Passing is not proof"*, *"Gates decay"*, *"The file is steady; the agent moves"*). The mood switch is what makes a declaration land inside an exercise, and it costs nothing because the nav rail and TOC are built from `##` headings already. Adding a rendered widget for declarations would box a thought that works better unboxed, and would retro-brand the one beat that earns it. **Action:** consider writing the heading-grammar convention into `check_slides.md` so the affordance is reliable rather than lucky. It also gives a cheap test at proposal time: a candidate declaration whose heading is a label rather than a claim is not a declaration yet.
