# Conflict-preserving learning OODA Cycle — 2026-09-08 14:37

**Focus area:** What a learning agent should do when two legitimate teachers, memories, or rules disagree.
**Research mode:** People-first practitioner synthesis, research evaluation, and adjacent policy-composition mechanisms.
**Why this focus:** Cycle 221 established that teaching authority is contextual. This round asks how the substrate retains disagreement without either freezing forever or flattening one local judgment into universal policy.

## Findings

### A factual conflict can often be removed by narrowing an over-broad rule

**Source:** https://arxiv.org/html/2607.13091v1 — [academic/research]
**Date:** 2026-07-13
**Who:** Aditya Aggarwal and Nahid Farhady Ghalaty
**What:** Their team encountered one genuine conflict: a general rule required disposal of every `IDisposable`, while a later rule prohibited disposing factory-created `HttpClient` instances. Code review established the framework fact, and the team refined the broad rule with a scope qualifier rather than deleting either underlying lesson.
**Evidence level:** L2 single-team field report, one reported conflict.
**Boundary:** This demonstrates factual resolution inside one team. It does not address two domains holding different but legitimate policies.

### Every treats unresolved contradiction as a state, not a license to guess

**Source:** https://github.com/EveryInc/compound-engineering-plugin/blob/8df67793b9733d2220fa9a7fc37139931471af62/docs/guides/ce-compound-refresh.md — [practitioner direct]
**Date:** Current implementation checked 2026-09-08
**Who:** Kieran Klaassen, Dan Shipper, and Every contributors
**What:** `ce-compound-refresh` checks set-level overlap, supersession, and contradiction before ordinary document drift. It can keep, update, consolidate, replace, split, or delete knowledge. Ambiguous unattended cases become explicitly stale rather than receiving a guessed replacement. If independent guidance conflicts with current code, the skill preserves the guidance and reports a possible product regression instead of silently rewriting the instruction to match the implementation.
**Evidence level:** L2 current single-team implementation; no measured later-task outcome.
**Boundary:** The system handles knowledge-store maintenance, not cross-team policy arbitration or executable permissions.

### Human disagreement can improve the rubric instead of merely choosing a winner

**Source:** https://hamel.dev/blog/posts/evals-faq/index.html — [practitioner direct]
**Date:** Modified 2026-09-01
**Who:** Hamel Husain and Shreya Shankar
**What:** Their current eval practice has annotators label shared cases independently, measure agreement, collect disputed examples, and use an alignment session to identify which rubric definition, rule, or example was missing. The revised rubric is then used to relabel affected cases; if disagreement remains, a named domain expert decides and records why.
**Evidence level:** L1 maintained practitioner method, informed by work with 50-plus companies and 700-plus learners; no public controlled comparison of this disagreement protocol.
**Key implication:** A conflict can reveal that the outer evaluation and promotion policy is underspecified. That is double-loop learning: update the rubric or ownership model, not only the immediate rule.

### Memory pipelines commonly erase the structure needed to handle conflict safely

**Source:** https://arxiv.org/html/2608.13921v1 — [academic/research]
**Date:** 2026-08-14
**Who:** Lu Yang, Shusheng Xu, Zhuoran Li, Tongkai Yang, and Longbo Huang
**What:** TANGLE evaluates 541 intentionally underdetermined cases across contextual, temporal/oscillating, and source-authority conflicts. In its pipeline track, Letta preserved the complete target conflict in 91.7% of cases, Mem0 in 69.1%, A-mem in 47.0%, and MemOS in 46.2%. Even with complete curated memory, models recognized conflict more reliably than they calibrated action or asked the resolving question.
**Evidence level:** L2 synthetic benchmark across five response models and four memory systems.
**Key implication:** Store the relation—who disagreed with whom, under what scope and time—not merely two retrievable text fragments. Retrieval fidelity is a safety property.

TANGLE's proposed action set is useful as a design vocabulary: `commit`, `conditionalize`, `clarify`, `verify`, `defer`, or run a `reversible_trial`. The paper shows why `latest wins`, majority vote, fixed source priority, and always-ask are insufficient universal policies. The result is research evidence, not a validated DevSecOps operating model.

### Restrictive composition is appropriate for controls, but not for truth

**Sources:** https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets; https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html — [vendor documentation]
**Date:** Checked 2026-09-08
**What:** GitHub aggregates all applicable rulesets and applies the most restrictive version when the same rule differs. AWS IAM combines permission sources under defined union/intersection rules, with explicit deny overriding allow.
**Evidence level:** L0 shipped capability.
**Boundary:** “Most restrictive wins” is a sound fail-closed default for authorization and merge controls. It is not a safe general rule for repository conventions, product behavior, or human intent, where over-restriction can be as wrong as over-permission.

## Orientation: Disagreement Is a First-Class Memory State

Two apparently conflicting lessons can mean four different things:

| Conflict class | Correct response |
|---|---|
| Factual error or over-broad rule | Verify the fact; refine or supersede the rule while retaining lineage |
| Context or scope partition | Keep both; encode the condition that selects each; clarify when the condition is missing |
| Temporal drift or oscillation | Keep the sequence and validity interval; verify current state rather than assuming newest means durable |
| Authority or policy conflict | Preserve both positions and route to the owners of the affected scope; do not let retrieval rank decide authority |

The learning system should therefore compound a **conflict record**, not a compromise sentence. At minimum it retains both claims, provenance, source authority, scope, valid time, evidence, the missing decision variable, affected actions, named resolver, current status, and safe action while unresolved.

## Decision: Conflict Protocol

1. **Detect and link:** retrieve the competing lessons as a conflict set.
2. **Classify:** factual, contextual, temporal, or authority/policy.
3. **Contain:** block high-impact promotion; keep existing restrictive controls in force.
4. **Test where testable:** use code, traces, counterexamples, or replay to answer factual questions. Tests inform policy owners but do not decide value trade-offs.
5. **Route:** send the conflict to the semantic and effect owners established in Cycle 221.
6. **Act proportionally:** commit, conditionalize, clarify, verify, defer, or run a reversible trial.
7. **Record the outer learning:** if the conflict exposed a missing scope, rubric, owner, or exception path, update that governance mechanism and relabel affected cases.
8. **Retain lineage:** resolved, rejected, superseded, and expired variants remain auditable so the system does not oscillate between forgotten positions.

## What I Looked For But Did Not Find

I found no public multi-team learning-agent deployment that preserves conflicting rule provenance through retrieval, automatically detects scope and authority collisions, routes them to the right owners, evaluates both sides, and measures downstream action quality. Current practitioner mechanisms each cover one part. TANGLE is synthetic and personal-memory-oriented; GitHub and AWS supply enforcement semantics, not organizational learning evidence.

## Training Implication

Module 9 can make disagreement the bridge into double-loop learning. Give learners three conflicting corrections to a DevSecOps ticket handler: a service-owner exception, a security baseline, and an incident-time request. The task is not “pick the best rule.” It is to produce the conflict record, identify the missing decision variable, choose the safe interim action, run the resolvable tests, and route the remaining policy choice. The outer-loop move is to repair the rubric, scope hierarchy, or exception path that allowed the conflict to remain implicit.
