# Learning-agent libraries and memory patterns OODA Cycle — 2026-09-07 18:22

**Focus area:** Which current libraries and memory forms people can apply to headless coding agents, and which part of the learning loop each actually supplies.
**Research mode:** Code analysis and cross-platform pattern.
**Why this focus:** Cycle 218 established that durable learning is a governed substrate change. This related round tests whether the visible agent and memory ecosystems supply that full loop or mainly execution, storage, and retrieval components.

## Findings

### Agent frameworks provide execution state, not a learning policy

**Sources:** https://github.com/langchain-ai/langgraph — [practitioner direct]; https://github.com/openai/openai-agents-python — [vendor documentation]; https://github.com/google/adk-python — [vendor documentation]; https://code.claude.com/docs/en/headless — [vendor documentation]; https://learn.chatgpt.com/docs/non-interactive-mode.md — [vendor documentation]
**Date:** Current repositories and live documentation checked 2026-09-07
**Agent level:** Team
**What:** LangGraph supplies durable execution, checkpoints, human inspection, and a long-term store. OpenAI Agents SDK and Google ADK supply sessions, tracing, guardrails, human-in-the-loop controls, and workflow primitives. Claude Code and Codex already run non-interactively. These components can host a learning loop, but none decides which trace deserves to become a rule or proves that the promotion improved a fresh run.
**Evidence level:** L0 capability evidence.
**Key claims:** Choose an orchestration framework for resume, routing, state, and observability. Do not count checkpoint persistence or conversation history as learning.

### The visible memory-library market clusters by the object being remembered

**Sources:** https://github.com/mem0ai/mem0 — [practitioner direct]; https://github.com/langchain-ai/langmem — [practitioner direct]; https://github.com/getzep/graphiti — [practitioner direct]; https://github.com/topoteretes/cognee — [practitioner direct]; https://github.com/letta-ai/letta — [practitioner direct]; https://github.com/vectorize-io/hindsight — [practitioner direct]; https://github.com/supermemoryai/supermemory — [practitioner direct]; https://github.com/memvid/memvid — [practitioner direct]
**Date:** Current repositories checked 2026-09-07
**Agent level:** Personal / team
**What:** The active choices are not interchangeable. Mem0 and LangMem focus on extracted facts, preferences, and semantic retrieval; Graphiti and Cognee focus on connected, changing knowledge; Letta couples memory to long-lived agent identity; Hindsight separates facts, experiences, observations, and mental models and can ingest coding sessions and git history; Supermemory combines profiles, knowledge, connectors, and forgetting; Memvid offers portable, versioned, single-file memory. Current GitHub attention is substantial—about 65k stars for Mem0, 31k Graphiti, 31k Cognee, 29k Supermemory, 25k Letta, 23k Hindsight, and 16k Memvid—but stars show ecosystem attention, not production adoption.
**Evidence level:** L0 capability and attention snapshot; no comparable independent production-usage denominator.
**Key claims:** Use semantic memory for preferences and facts; temporal graph memory for changing relationships and provenance; identity memory for a long-lived persona; portable memory for local or offline deployment. No benchmark winner settles the choice because these systems remember different objects and their reported results are not directly comparable.

### Coding-agent “learning” is mainly procedural and evaluative memory

**Sources:** https://code.claude.com/docs/en/memory — [vendor documentation]; https://learn.chatgpt.com/docs/agent-configuration/agents-md.md — [vendor documentation]; https://github.com/EveryInc/compound-engineering-plugin — [practitioner direct]; https://github.com/google-research/reasoning-bank — [academic/research]
**Date:** Live documentation and current repositories checked 2026-09-07
**Agent level:** Personal / team
**What:** For bug handling, the useful durable object is usually a procedure or check: `CLAUDE.md`/`AGENTS.md`, a scoped rule, skill, test, linter, hook, or harness change. Every's plugin is the most visible coding-specific implementation in this sweep, with roughly 25k GitHub stars and a loop that captures learnings for later work. ReasoningBank is the clearest research implementation of successful and failed trajectories becoming reasoning memory and later SWE-bench input. Neither supplies the full human-gated promotion, paired replay, expiry, and retirement system.
**Evidence level:** L2 implementation/research evidence from cycles 211–213; ecosystem-attention counts are L0.
**Key claims:** The memory forms relevant to Module 9 are: raw episodic traces; semantic project facts; procedural rules and skills; evaluative cases and outcomes; and governance metadata covering source, authority, scope, owner, and expiry. Most memory libraries cover the first two or three. The promotion ledger and eval gate remain application code.

## Current Shortlist by Need

| Need | Start with | What it is not |
|---|---|---|
| Fresh headless coding run with durable team behavior | `CLAUDE.md` / `AGENTS.md`, scoped rules, skills, Git | A database or autonomous learner |
| Resumable multi-step workflow and human pause | LangGraph; alternatively the SDK native to the chosen model ecosystem | Proof that behavior improved |
| Facts, preferences, user/project context | Mem0, LangMem, Supermemory | Safe procedural promotion |
| Time-varying relationships and source lineage | Graphiti; Cognee for broader document/code graph ingestion | An authority model |
| Long-lived agent identity | Letta | A coding-specific learning loop |
| Session/git-derived experience and synthesized observations | Hindsight | A proven human-gated promotion system |
| Portable or offline versioned context | Memvid | Automatic learning governance |
| Coding-specific procedural reuse | Every compound plugin; ReasoningBank as research reference | A complete production control plane |

## What I Looked For But Did Not Find

I found no independent denominator showing which specialist memory library is most used in production, and no public head-to-head on real bug-fix agents that includes repairs, regressions, security, cost, forgetting, and later-session harm. The current leaders publish incompatible or vendor-run memory benchmarks. I also found no mainstream package that joins raw trace retention, human correction, authority-aware candidate generation, paired replay, promotion, selective loading, monitoring, expiry, and rollback.

## Orientation

For a Claude Code or Codex bug agent, begin with the boring stack: JSONL traces and verified outcomes as episodic evidence; Git-versioned candidate rules/skills/tests; a human promotion ledger; and paired fresh-run evals. Add LangGraph only when the execution really needs durable orchestration. Add a specialist memory server only when the retrieval problem is concrete—large history, temporal relationships, cross-repo knowledge, or long-lived identity. **A vector store is storage; a memory library is retrieval plus consolidation; a learning agent additionally needs governed promotion and proof.**
