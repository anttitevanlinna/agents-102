### Finding 2: HydraFusion Day+14 — L3 CONFIRMED; Cross-Vendor L4 Meta-Pattern Emerging

**Source:** [github.com/orgs/community/discussions/206492](https://github.com/orgs/community/discussions/206492) — [practitioner direct, forum]
**Date:** Post-Sep-13 comments (Day+14 window)
**Agent level:** personal / team
**What:** GitHub community discussion now shows active Day+14 practitioner convergence. Two independent patterns at L3: (1) **Cost savings confirmed in-wild** — one user "30% of turns" routed to mai-code-1.1-flash "for very little cost"; another confirms real-world cost in the "10% of what I'm used to" range vs Opus 5 exclusive. (2) **Systematic opacity problem** — "all I can see is the question…when I cancel the interaction and it dumps all the info into the CLI I can finally see what it thought"; CLI flag `--model hydrafusion` doesn't work directly (requires env var workaround); cancellation is unresponsive ("It seems to work a lot before finally stopping"); no per-request model identity visible. Multiple users reporting both patterns independently, Day+7 through Day+14.
**Evidence level:** Level 3 (multiple independent users in a community thread independently reporting the same two patterns — cost savings AND opacity)
**Key claims:**
- Cost savings: 30–90% token reduction confirmed in-wild; quality not noticeably degraded in routine tasks
- Opacity: four distinct visibility failures — hidden intermediate outputs, invisible model identity, non-functional CLI flag, cancellation lag
- Both patterns consistent across users who don't appear to have read each other's comments (chronology suggests independent discovery)

**Source:** [memorylake.ai/en/blogs/copilot-hydrafusion-per-request-context](https://www.memorylake.ai/en/blogs/copilot-hydrafusion-per-request-context) — [practitioner analysis]
**Date:** September 2026
**What:** Per-request model routing structurally prevents any single model from accumulating project context across tasks. The critic model operates as an "independent read-only critic from a different model family" that cannot access tools. Cites Sourcegraph Amp as independent corroboration: composed execution architectures "buy efficiency at the cost of non-retained intermediate knowledge."
**Evidence level:** Level 4 (cross-domain meta-pattern: HydraFusion + Sourcegraph Amp independently demonstrate the same architectural tradeoff — per-request routing vs. context continuity. Two separate product teams, same mechanism, same tradeoff.)
**Key claims:**
- Per-request routing = structural context discontinuity across tasks (fundamental architectural tradeoff, not a bug)
- Sourcegraph Amp independently arrived at the same tradeoff — cross-vendor L4 confirmation
- CTO framing: for tasks requiring project-level context across sessions, per-request routing is not the right architecture

**Source:** [pondero.ai/coding/guides/github-copilot-hydrafusion-september-2026/](https://pondero.ai/coding/guides/github-copilot-hydrafusion-september-2026/) — [practitioner analysis]
**Date:** September 2026
**What:** Deconstruction of GitHub's vendor benchmarks. 67% cost headline holds on TerminalBench only. Second benchmark (CheckpointBench): 65% savings for rounding-error quality change. Third benchmark (DeepSWE): 36% savings with 1.5 quality-point regression. First-turn, single-prompt tasks are the best use case — "multi-turn iterative performance is a stated future focus."
**Evidence level:** Level 2 (single analysis source)
**Key claims:**
- 67% headline = best case (one of three benchmarks); 36% is the worst case
- Quality regression confirmed on DeepSWE: 1.5 quality-point reduction at 36% cost savings
- Use case fit: first-turn / single-prompt tasks; not validated for multi-turn iterative

## Orientation

HydraFusion Day+14 is the headline finding this cycle: L3 confirmed on both the cost-savings pattern AND the opacity pattern from independent community practitioners. More significant: the MemoryLake + Sourcegraph Amp cross-vendor analysis suggests an L4 meta-pattern — per-request multi-model routing buys cost efficiency but structurally sacrifices context continuity. Two independent products (GitHub Copilot HydraFusion, Sourcegraph Amp) have arrived at the same architectural tradeoff. CTOs evaluating multi-model routing architectures now have a documented structural limitation to weigh, not just a feature gap to wait for a fix on.

OpenAI Agents API Day+8 is notable for what's absent: three non-adoption accounts but zero production deployers. The commodity-harness observation is now a multi-source pattern. The two-week gap between Assistants API shutdown (Aug 26) and Agents API launch (Sep 10) suggested migration urgency; the early adoption picture shows the migration audience isn't primarily moving to Agents API — they're evaluating trigger-native tools (n8n, etc.) instead.

v2.1.275 per-command `allowed_domains` in Bash/PowerShell/Monitor is quietly significant: operators can now restrict which domains each shell command can reach in auto mode. This is the first granular per-command domain allowlist, filling a governance gap that prior cycles flagged (containment escape rules v2.1.257 blocked credential fetch/egress/cross-tenant at the model layer; this blocks at the shell-command layer).
