### Finding 2: Rehberger / Claude Code Auto Mode — Anthropic's Official Statement Acquired; "Working as Designed"

**Source:** [theregister.com/research/2026/08/28/researcher-shows-how-claude-code-can-be-tricked-simply-by-asking-it-to-summarize-a-website/5293372](https://www.theregister.com/research/2026/08/28/researcher-shows-how-claude-code-can-be-tricked-simply-by-asking-it-to-summarize-a-website/5293372) — [domain trade publication]

**Date:** 2026-08-28
**Agent level:** company
**What:** Anthropic's official response to Rehberger's disclosure now acquired: "Auto Mode is a convenience feature backed by a best-effort classifier, not a security guarantee." Anthropic characterized the behavior as "working as designed" and stated the classifier is not built to stop determined prompt-injection chains of individually benign steps. Rehberger's recommendation: "Do not trust the model output" — genuine security depends on OS isolation and network egress controls, not the classifier. No security blog, architectural guidance, or behavioral change announcement from Anthropic found at Day+5. Code patch (v1.0.93/94) remains the only confirmed Anthropic response.
**Evidence level:** Level 2 (practitioner attack disclosure + official vendor statement)

- No Anthropic security blog or architectural guidance post-Rehberger at Day+5
- Correct enterprise security posture: OS-level sandboxing + network egress controls, NOT reliance on model classifier
- CTO implication: teams using Claude Code in CI/CD or autonomous agent pipelines with external web access must architect OS-level isolation independently of auto mode
