## Findings

### Fixed-model harness evolution works locally but transfers weakly

**Source:** https://arxiv.org/abs/2604.25850 — [academic]
**Date:** 2026-04-28
**Agent level:** Team
**What:** Agentic Harness Engineering distills coding-agent rollouts into reports, attributes outcomes to the prior change, lets an evolver edit file-represented harness components, and keeps or reverts the revision after evaluation. One Terminal-Bench 2 campaign moved from 69.7% to 77.0%, but frozen SWE-bench Verified transfer moved only from 75.2% to 75.6% and several repositories regressed.
**Evidence level:** L2 single research program.
**Key claims:** The base model stays fixed; the editable surface is the external harness; changes are versioned and reversible; aggregate transfer was small and uneven.

### Paired verification makes rule admission testable

**Source:** https://arxiv.org/abs/2605.10999 — [academic]
**Date:** 2026-05-09
**Agent level:** Personal
**What:** SkillGen contrasts successful and failed trajectories, synthesizes a readable skill, runs the same verification cases with and without it, and selects on net repairs minus regressions. A later candidate could look plausible yet score -3.1 points while a previously verified version remained +8.1, making the admission gate load-bearing.
**Evidence level:** L2 single research program; not repository-level SWE evidence.
**Key claims:** Candidates are compared against a no-skill condition; repairs and regressions are counted separately; active and deprecated states support rollback.

### Trace-derived SWE skills can shape training, but this is not lightweight memory

**Source:** https://arxiv.org/abs/2606.07412 — [academic]
**Date:** 2026-06-05
**Agent level:** Team
**What:** Socratic-SWE distills historical repair traces into structured skills, uses those skills to generate targeted executable repair tasks, then updates model weights. It reached 50.40% on SWE-bench Verified after three iterations, but the process used 36,000 generated training instances and nearly plateaued by iteration five.
**Evidence level:** L2 single research program.
**Key claims:** Traces can expose recurring failures and useful repair behavior; execution-grounded validation matters; the durable improvement here is mainly weight training, not a repo rule loaded by a later off-the-shelf agent.

### More memory is not reliably better

**Source:** https://arxiv.org/abs/2606.15017 — [academic]
**Date:** 2026-06-12
**Agent level:** Personal
**What:** In a token-matched WebArena comparison, a vanilla actor matched or beat three augmented memory or self-improvement methods in aggregate. Separate recent work found that random or excessive memory can degrade results, and an agent's own success judgment can be unreliable.
**Evidence level:** L2 counter-evidence; web tasks rather than repository repair.
**Key claims:** Reflection, retrieval, and verification tokens must be counted; memory needs selective loading and external outcome checks.

## What I Looked For But Did Not Find

No recent primary study tests the exact classroom sequence: a Claude Code bug trace plus stored human correction, a reviewed candidate rule, and a fresh comparable bug solved by the same fixed base agent. No located experiment isolates the causal value of a human promotion gate. Security and regression evidence also shows that utility can rise while unsafe behavior rises.

## Orientation

The research supports **controlled external artifact improvement**, not the broad phrase “the agent learns.” The defensible loop is trace → candidate rule with provenance → paired no-rule/rule test → human decision → selective fresh-session load → measure repair, regressions, tokens, and rollback. Evidence remains L2, not convergence.
