# Exercise: Design the sharing plan

**Time:** 23 minutes.

`module-7/jtbd.md` names the job. `module-7/branch.md` names the candidate. Now find the obstacle that decides whether the teammate can absorb it, then draft both halves of the plan.

## Find the absorption bottleneck

*5 min*

The obstacle is usually not the first technical limitation a builder sees. The agent compares the technical, social, political, habitual, governance, and trust obstacles and writes the load-bearing one.

{{prompt:share-your-work-3}}

Open `module-7/absorption-bottleneck.md`. A good bottleneck explains why several other obstacles stay hard. If removing it would solve only itself, ask the agent to cluster the obstacles again.

## Draft both plans

*18 min*

The technical plan and people plan carry equal weight. Missing names stay visible as `UNASSIGNED — Monday's question`; the agent does not invent them.

{{prompt:share-your-work-4}}

Compare the two files. `module-7/technical-plan.md` should name what moves the outcome and the first real test. `module-7/people-plan.md` should name who owns, governs, operates, judges, and propagates it.

A polished technical file beside a people file full of unnamed roles is the finding, not a finished rollout.

[Test the sharing plan](test-the-sharing-plan.md) checks the assumptions underneath these plans, imagines the failure, and writes the first real-world contact to `module-7/monday.md`.
