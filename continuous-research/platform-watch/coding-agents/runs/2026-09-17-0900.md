### Finding 2: OpenAI Agents API Day+7 — First Practitioner-Direct Evaluation Found (Non-Adoption; Data Residency + Terminal Capability as Blockers)

**Source:** [github.com/eyecantell/agentorc/pull/134](https://github.com/eyecantell/agentorc/pull/134) — [practitioner direct]
**Date:** September 2026 (post-Sep-10 launch; exact date not specified)
**Agent level:** personal / team
**What:** eyecantell, a named developer building agentorc (an autonomous agent orchestration system), evaluated the OpenAI Agents API as a potential substrate or adapter and decided NOT to adopt it. Reasons: (1) **No terminal capability** — "No pty, no pane, no local checkout, OpenAI models only" — incompatible with their argv/pane-classifier architecture; (2) **Data residency concern** — US-only processing with no zero-downtime recovery option; (3) **Vendor lock-in risk** — "The predecessor Assistants API sunset two weeks prior, arguing against vendor session state dependency." Four lessons extracted and incorporated as design inputs (not as implementation choices): session/turn terminology distinction (idle vs. active), structured `required_actions` payload pattern, split error states (`session.failed` vs. `session.environment.failed`), stream replay principle. Meta-observation: "Managed cloud agent runtimes on token billing are now commodity offerings across vendors" — platform neutrality confirmed as a design principle.
**Evidence level:** Level 2 (practitioner-direct non-adoption evaluation; named person + named project + specific technical rejection criteria)
**Key claims:**
- First practitioner-direct account of evaluating the OpenAI Agents API post-launch
- Non-adoption reasons reveal real deployment blockers: no terminal/pty, US-only data residency, vendor session-state risk
- Architectural lessons extracted even from rejected substrate — four patterns incorporated as design inputs
- "Managed cloud harnesses are commodity" — validates competitive framing across Anthropic Managed Agents and OpenAI Agents API; differentiator is execution environment control, not harness sophistication
