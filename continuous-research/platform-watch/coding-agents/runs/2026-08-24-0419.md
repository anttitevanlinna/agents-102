**What:** Multiple independent developer voices report the same behavioral pattern: Opus 5 defaults to maximum scope interpretation, treats minor issues as high-severity, and generates far more code than requested. ### Fable/Opus selection framework — L3 convergence

**Source:** https://thenewstack.io/opus-5-vs-fable-5/ — [domain trade publication]; https://prosperinai.substack.com/p/opus-5-vs-fable-5-selection-guide — [practitioner analysis]; https://every.to/context-window/taming-opus-5 — [domain trade publication]
**Date:** August 2026
**Agent level:** personal / team
**What:** Multiple independent publications converging on the same decision framework: use Fable 5 for exploration (open-ended problems, novel reasoning, pre-specification work) and Opus 5 for convergence (execution against defined spec, scoped refactors, bounded puzzles). For long-running agents: split — Fable for planning phase, Opus for execution phase. Opus 5 positioned as "near-Fable intelligence at half the price" for appropriate use cases. Selection criterion is task open-endedness, not complexity.
**Evidence level:** Level 3 (three independent sources converging on same framework)
**Key claims:** (a) Fable 5 for exploration; Opus 5 for convergence — selection axis is open-endedness; (b) 2x cost differential ($5/$25 vs $10/$50); (c) agentic pipeline split: Fable plans, Opus executes

### Every.to compound engineering friction — root cause and resolution documented

**Source:** https://every.to/context-window/taming-opus-5 — [domain trade publication]
**Date:** July 28, 2026
**Agent level:** team
**What:** Kieran Klaassen (Every.to GM) identified the root cause of Opus 5's compound engineering stop behavior: a legacy "handoff" instruction in the compound engineering plugin directing the model to pause and defer to another agent (which no longer existed). Removing the outdated instruction resolved the stop-between-steps pattern. The fix approach: run identical tasks with and without the skill, compare across fresh sessions, remove specific problematic instructions. Finding aligns with Anthropic's own Claude Code system prompt reduction (80% shorter, no performance degradation) — verbose legacy instructions are architectural debt that degrades newer models.
**Evidence level:** Level 2 (single organization, documented root cause + specific resolution)
**Key claims:** (a) Opus 5 compound engineering friction was a prompt debt problem, not a model capability gap; (b) removing a single legacy instruction resolved the stop behavior; (c) August 12 vibe-check update with full resolution verdict is behind paywall — partial resolution confirmed
