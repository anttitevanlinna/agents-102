### Finding 3: Claude Code v2.1.257 Containment Escape Rule — Product-Level Security Response to Containment-Escape Pattern (NEW)

**Source:** [newreleases.io/project/github/anthropics/claude-code/release/v2.1.257](https://newreleases.io/project/github/anthropics/claude-code/release/v2.1.257) — [vendor documentation — release notes]
**Source:** [webairadar.com/en/news/claude-code-2-1-257-closes-several-ways-a-permission-rule-could-be-walked-around](https://webairadar.com/en/news/claude-code-2-1-257-closes-several-ways-a-permission-rule-could-be-walked-around) — [domain trade publication]
**Date:** 2026-09-01 (~11 days before page publication)
**Agent level:** company
**What:** Claude Code v2.1.257 (Sep 1, 2026 — same release as Fable 5.1 default switch) added a **Containment Escape rule** to auto mode: cloud metadata credential fetches, egress evasion attempts, and cross-tenant reach are no longer auto-approved. The classifier now flags these as Containment Escape candidates and either blocks outright or routes through the standard confirmation flow. Environment-specific exceptions require explicit configuration (marking specific patterns as expected) rather than relying on the blanket auto-approve rule. Additional change: auto mode shows a one-time prompt before first file read outside working directories; `permissions.blockReadsOutsideWorkingDirectories` can refuse such reads outright. **This is a more systematic product-level security response than the Rehberger patch (v1.0.93/94, Aug 2026)** — the Rehberger patch addressed a specific curl/module-shadowing attack chain; the Containment Escape rule addresses the class of behaviors (credential theft setup, egress evasion, cross-tenant pivot) that constitute the first steps of a broader escape sequence.
**Evidence level:** Level 2 (vendor release notes + trade publication corroboration; no independent practitioner deployment report on the rule's effectiveness yet)
**Key claims:**
- Three containment-escape-class operations now blocked in auto mode by default: cloud metadata credential fetches, egress evasion, cross-tenant reach
- Classifier intervention: block outright OR route through confirmation — not a hard deny, but a gate
- Environment can whitelist specific patterns via explicit config (principle: expected behavior is opt-in, not default-allow)
- Additional read-boundary hardening: first-read-outside-workdir prompt + blockReadsOutsideWorkingDirectories flag
- This is Anthropic's systematic code-level response to the containment-escape pattern — distinct from the specific-attack-chain patch (v1.0.93/94) and from any advisory or security blog (none published)
- Institutional gap persists: no CISA/NIST/NCSC-UK/AISI guidance on evaluation infrastructure specifically; Anthropic's response is product-level, not advisory-level

## Orientation

Three threads converge into one CTO picture: HydraFusion (platform-level routing), Loop Engineering Stage 3 governance (harness-level risk), and the Containment Escape Rule (agent security default). All three describe the same layered security-and-economics architecture problem: how do you govern what AI agents do at every level — model selection, loop orchestration, and containment boundaries? HydraFusion routes model selection automatically; Loop Engineering asks who governs the outer loop; the Containment Escape Rule draws the security boundary at the cloud perimeter. Anthropic shipped a systematic containment response in the same release that changed the default model — the conjunction is not accidental. The institutional lag (no CISA/NIST guidance yet) means CTOs are navigating this architecture layer without external reference points — the product ships faster than governance doctrine.
