### [Finding 2] Assistants API August 26 — 31-day countdown; Azure-fork same date; no new migration tooling

**Sources:**
- https://community.openai.com/t/assistants-api-beta-deprecation-august-26-2026-sunset/1354666 — [vendor official announcement] (Aug 26, 2025; thread active July 2026)
- https://learn.microsoft.com/en-us/answers/questions/5790094/will-azure-openai-assistants-api-specifically-be-d — [vendor documentation] (July 2026)
- https://www.socialcrawl.dev/blog/openai-assistants-api-2026-shutdown-migration-guide — [practitioner analysis] (May 11, 2026, updated July 22, 2026)

**Date:** July 26, 2026 check
**Agent level:** company
**What:** August 26, 2026 is the hard stop date for BOTH OpenAI direct and Azure OpenAI Assistants API endpoints. After that date, every call to `/v1/assistants`, `/v1/threads`, `/v1/threads/runs` returns an error — no degraded mode, no grace period. Microsoft confirms identically: "The Assistants API is deprecated and will be retired on August 26, 2026." Both targets (Responses API for OpenAI direct; Microsoft Foundry Agents for Azure) confirmed.

Scale context (socialcrawl.dev, updated July 22): estimates ~2.1M developers on OpenAI platform; Assistants is "a single-digit slice" of 2.2B daily API calls but the absolute count of production systems pointed at those endpoints is large. No automated thread migration tool — developers must manually handle Threads-to-Conversations backfill (three options: archive, expensive backfill, accept data loss). Engineering effort: 1-4 weeks for small production systems; prior cycles documented 9-12 months for enterprise. "The teams getting this right are not the ones with the most engineering capacity. They are the ones who started before the panic."

Community thread trust erosion (no new data this cycle — consistent with prior cycles 168-172): practitioners asking "Is the new API a beta as well? How can we trust it won't also experience the same treatment?"

**CTO implications this cycle:**
- 31 days to hard stop. Any team that hasn't started is now at risk for small systems; enterprise teams should have been running for months.
- Azure → Foundry Agents and OpenAI direct → Responses API are architecturally separate migration targets. A team on Azure OpenAI Assistants migrating to Foundry Agents is NOT following the OpenAI migration guide.
- The June 30 → August 26 window shrinking: teams that started on June 30 (when first cycles began tracking this) now have 27 days of history, leaving 31 to hard stop.

**Evidence level:** L0 (official announcements) for hard stop date and no-automated-tool confirmation; L2 (practitioner analysis) for migration effort estimates
**Key claims:**
- August 26, 2026 hard stop — FIRM, no extension, OpenAI staff confirmed
- Azure OpenAI Assistants = same August 26 date; migration target = Foundry Agents, NOT Responses API
- No automated thread migration tool — by design, per official guide
- ~2.1M OpenAI developers; production systems count unknown but large
- 1-4 engineering weeks for small systems; 9-12 months for enterprise (prior cycle estimate, not refreshed this cycle)
