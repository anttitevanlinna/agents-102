# Squint test — A101 skeleton to-be

## 1. Big learnings

- Context isn't given, it's authored — "Context is whatever you tell it"
- The model replays the whole conversation each turn — "It reads the whole conversation every time"
- The system reflects the user's own input back — "It amplifies what you bring"
- An agent's self-report is a claim to check, not a fact — "The report is a hypothesis, not a result"
- Retros go easy on people because agreement felt good — "Why the retro was kind to you"
- You test a model of the world by acting and watching what breaks — "You act on the future to know what's real"
- Compounding systems improve through revision, not raw cleverness — "It gets better by being edited, not by being clever"
- If knowledge isn't written down, the agent can't draw on it — "What you haven't written down, it can't use"
- Models will keep changing but the memory/system built around them persists — "The model will change under this; the memory won't"
- Fixing a bug means fixing the rule that let it happen, not just the output — "Fix the output, then fix the rule that let it through"
- The default stance toward splitting an agent is not to — "Start with don't"
- Splitting only pays off when the roles genuinely can't coexist in one agent — "Splitting earns its keep when they can't be one"
- A single summarizing agent, unchecked, regresses to bland consensus — "Left alone, the synthesizer averages to beige"
- Certainty about these systems is an inherited, false comfort — "Certainty is a fantasy you inherited"
- The old "employee reads a doc" trust model doesn't hold for agents — "No employee reads every document as an instruction"
- The strongest safeguard is simply not granting an opening — "The best mitigation is the door you don't open"
- Admitting uncertainty is a legitimate output, not a failure — "'I can't tell' is a real answer"
- High average accuracy across many uses still yields frequent real failures — "Mostly right, ten times over, is mostly wrong"
- A confident-sounding self-check is not verification — "'Are you sure?' is another fluent answer"
- Any judge/evaluator has its own boundary of competence — "The judge names its own limit"
- Consistency across repeated runs signals drift, not correctness — "A drift signal, never proof"
- A metric that can be redefined at will stops functioning as a metric — "A yardstick you rewrite is not a yardstick"
- An unmoving score tells you something about the judge, not the system — "A flat score is information about the judge"
- Approval gates encode a judgment call, not neutral fact — "The gate is a claim too"
- As agents improve, human oversight moves to a higher, less granular level — "The human moves one level up"
- Better performance tends to reduce how closely humans actually check it — "The better it gets, the less you watch"
- Absorption of a shared agent is not automatic just because access is granted — "Access is easy; absorption is scarce"
- People take in new capability only to the extent they already partly understand it — "People absorb what they already half know"
- A team that builds tool-building tools compounds its own capability — "The tool that builds tools compounds"
- The end state is continuous renewal, not a finish line — "A flywheel, not a graduation"

## 2. Governors

- Before splitting an agent into multiple roles, default to not splitting — "Start with don't"
- Before delegating an action, ask whether you'd actually let it send the message — "Would you let it send the mail?"
- Before trusting a good-looking track record, ask what would change your mind about it — "What would change our mind?"
- Before accepting a system's score as settled, ask whether a competitor could make the same claim — "Could a competitor claim this?"
- Before assuming oversight is happening, ask when you personally last read one of the outputs — "When did you last read one of these yourself?"
